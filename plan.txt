I. PROJECT OVERVIEW
---------------------------------------------------------

Goal:
-----
Tee Time Snipe helps golfers catch open tee times that fit their schedule before others do. 
It monitors supported booking platforms (starting with ForeUp) and immediately notifies the user 
when a matching tee time opens up.

Core Philosophy:
----------------
- Respect provider Terms of Service (no auto-booking)
- Focus on timely alerts, simple user experience, and accurate notifications
- Validate demand before scaling infrastructure
- Build leanly on Always-Free and developer-friendly cloud tools

IV. SUPABASE DATABASE STRUCTURE
---------------------------------------------------------

1. user_profiles
----------------
- id (uuid) → references auth.users(id)
- full_name
- phone
- expo_push_token
- membership_tier_id → references membership_tiers(id)
- stripe_customer_id
- created_at / updated_at timestamps

2. membership_tiers
-------------------
- id (serial)
- name ('Free', 'Plus', 'Pro', etc.)
- description
- price_cents
- max_alerts
- scan_interval_seconds

3. courses
----------
- id (bigserial)
- name, city, state, provider, provider_course_id, provider_url
- latitude, longitude, time_zone
- active (boolean)

4. provider_configs
-------------------
- course_id → references courses(id)
- provider (e.g., 'ForeUp')
- key (e.g., 'schedule_id', 'booking_class')
- value (string or JSON)

5. availability
---------------
- id (bigserial)
- course_id → references courses(id)
- tee_time (timestamptz)
- price (numeric)
- holes (int)
- data (jsonb)
- scanned_at (timestamptz default now())
UNIQUE (course_id, tee_time, holes)

6. alerts
---------
- id (bigserial)
- user_id → references user_profiles(id)
- course_id → references courses(id)
- holes (int)
- date_from/date_to (timestamptz)
- start_time/end_time (timestamptz)
- active (boolean)
- created_at / updated_at timestamps

7. alert_notifications
----------------------
- id (bigserial)
- alert_id → references alerts(id)
- availability_id → references availability(id)
- sent_at (timestamptz)
- via (text)
- status (text)

V. HOW THE SYSTEM WORKS
---------------------------------------------------------

1. Course Initialization
   - Admin seeds 30–50 ForeUp courses
   - Each course has provider configs for ForeUp parameters

2. User Flow (Frontend → Backend)
   - User browses courses and sets preferences (holes, date/time window)
   - User fills out alert settings **without being logged in**
   - Upon pressing “Submit,” app prompts user to create an account
   - After authentication via Supabase → app saves alert via REST API
   - Backend inserts record into `alerts`
   - User is now “subscribed” to that alert

3. Background Scanning (Backend)
   - Scheduled or manually triggered runs call ForeUp API per course
   - Stores results in `availability`

4. Alert Engine
   - On each scan:
     * Checks every active alert
     * Matches available tee times to alert windows
     * If a new match that hasn’t been sent before → insert into `alert_notifications`
     * Triggers push/email notification via `notify_user()`

5. Notification Delivery
   - Backend sends pushes to Expo or Firebase APIs
   - Users receive notifications on mobile even if app closed
   - Tapping notification opens course booking page (`provider_url`)

6. Frontend Views
   - Course Picker
   - Alert Creation Flow (with Guest → Sign-Up redirect)
   - “My Alerts” Dashboard
   - Notification History Feed
   - Profile Settings (manage plan & push opt-ins)
